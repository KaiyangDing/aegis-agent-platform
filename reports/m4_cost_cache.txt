M4.6 实验②：精确缓存降本（执行 2026-08-03 23:27:29Z → 2026-08-03 23:47:36Z，run_tag=691dcd82）
========================================================================
1. 实验口径
- 模拟流量：140 条唯一问题（cost_questions.json cache 节，与实验①/评测集零交集）
  经 build_cache_traffic(replay_ratio=0.3, seed=42) 扩成 200 条请求、恰 60 条复述；
  分布假设显式声明：30% 历史复述（从已流出前缀均匀重抽，逐字节同串）；
  唯一池意图构成 FAQ 30%(42)/RAG 40%(56)/工具 20%(28)/闲聊 10%(14)，工具题只读；
- 驱动：ChatService 生产编排进程内直驱（正常分诊路由），每请求一个新会话——
  缓存 key 只哈希语义本体（tier/messages/tools/温度/上限），session_id 不入哈希，
  跨会话复述照样命中（cache.py:38-42）；
- 相位：先 C（缓存关）后 D（缓存开 TTL=3600，先 FLUSH 实验租户键冷启动）——
  同流量同序两遍；控制变量装配后断言核验；故障注入 0；预算闸关闭；
- 分账：相位间精确 sid 清单（附录），数字可由 usage_ledger 复算；预算 600000；
- 检索 embedding 无缓存语义、两相位等价支出，不计入对照（tier<>'embedding'）。

2. 原始数字（usage_ledger 聚合，tier<>'embedding'）
- off: 请求 200/200，LLM 调用 424（cached 0），prompt 252999，completion 10246，cost ¥0.190707
- on: 请求 200/200，LLM 调用 423（cached 121），prompt 249359，completion 10254，cost ¥0.148905
- embedding 另账（setup 语料种子+两相位检索查询向量）：294 行，3346 token，¥0.001744

3. 结果与命中率自检
- 命中率自检：设计复述 60/200；相位 on 请求级全命中=复述 60/60、
  首现误命中 0（应 0）、相位 off 全命中 0（应 0）；与设计吻合
- 精确缓存降本（30% 复述假设下）：21.9%（C→D，同流量 200 条）
- 限定语：数字只在「本流量构成 + 30% 复述假设 + 本价目表」口径下成立；
  复述率是声明性假设——真实流量的降本随实际复述率单调变化，本实验不外推。

4. 威胁与边界
- 30% 复述是声明的分布假设不是线上实测（生成器与种子公开，构成可审计可重放）；
- 价目为演示值（config.py model_prices）——降本%是同一价目表内的相对量；
- 不预设目标值（04 M4）；精确缓存只对逐字节相同请求生效，措辞略异即 miss——
  本数字是精确缓存的上界口径（语义缓存归 v2，00 §10.3）；
- LLM 输出长度方差使 C 相位成本有自然波动；D 相位命中部分零方差。

附录 A：聚合/自检 SQL（sids 取附录 B 对应相位清单）
  SELECT count(*) AS calls, count(*) FILTER (WHERE cached) AS cached_calls, coalesce(sum(prompt_tokens), 0) AS p, coalesce(sum(completion_tokens), 0) AS c, coalesce(sum(cost), 0) AS cost FROM usage_ledger WHERE session_id = ANY(:sids) AND tier <> 'embedding'
  SELECT session_id FROM usage_ledger WHERE session_id = ANY(:sids) AND tier <> 'embedding' GROUP BY session_id HAVING bool_and(cached)
