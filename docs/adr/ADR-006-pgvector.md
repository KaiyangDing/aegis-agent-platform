# ADR-006 · pgvector 而非独立向量数据库

**状态**：Accepted（v1.1 评审修订）　**日期**：2026-07

## 背景

RAG 需要向量检索。选择：PostgreSQL + pgvector 扩展，或独立向量库
（Milvus / Qdrant / Weaviate 等）。

## 决策

**PostgreSQL 16 + pgvector ≥ 0.8.0**，chunks 表上建 HNSW 索引。
部署要求写死版本下限——0.8.0 的 `hnsw.iterative_scan` 是下文召回完整性方案的依赖。

## 理由

1. **规模匹配**：本项目每租户文档量在万级 chunk 以下——pgvector 的 HNSW 在这个量级的
   召回率与延迟完全够用；独立向量库的优势区间（十亿级、高 QPS、GPU 加速）远超本项目需求；
2. **事务一致性**：文档元数据、权限、chunk 向量在同一个库——摄取流水线一个事务写完；
   更重要的隐藏红利：**事件流与投影表"同事务派生"也因单库而零成本**（见架构 §3）；
3. **多租户过滤（评审后的严谨表述，拆成两层）**：
   - **越权隔离**：由 SQL `WHERE tenant_id = ?` + PG RLS 兜底保证——这一层是硬的；
   - **召回完整性**：单独保证。HNSW 的 WHERE 本质是"索引内后过滤"——先按 ef_search 取
     最近候选、再在候选上应用过滤，小租户的行在候选集中可能不足 top-k 甚至为零。
     方案：开 `hnsw.iterative_scan=relaxed_order`（候选不足时继续扫描）；
     备选：小租户直接精确扫描——万级 chunk 全扫描既正确又够快，这反而强化了
     "本项目规模用 pgvector 足够"的选型论证。
     **旧表述"隔离在检索时发生所以没有检索后过滤问题"是错的，面试官一句
     "HNSW 怎么执行这个 WHERE"就能打穿——现在这两层表述才是标准答案**；
4. **运维减半**：少一个有状态组件，备份/迁移/监控一套方案。

## Embedding 选型（v1.2 按开发环境敲定：百炼 text-embedding-v4）

- **模型**：阿里云百炼 `text-embedding-v4`，显式指定 `dimensions=1024`（v4 支持多档输出维度，
  固定 1024 即 `vector(1024)` 的来源；具体批量上限等参数以 M3 时百炼文档实测为准）；
  RAG 语料、长期记忆、（v2 的）语义缓存三个用途共用同一模型，向量空间一致；
- **形态**：API 调用，摄取流水线是 **IO 密集**——Celery worker 里做批量调用、供应商限流、
  退避重试与断点续传（一批失败不重跑全量）；embedding 调用同样过网关计量，计入 usage_ledger；
- **为什么不用本地 bge-m3（原方案，降级为 v2 离线选项）**：与 LLM 同平台一个 key、
  零部署负担、Windows 开发机不用装 torch；代价是按量付费（极低）与配额依赖——
  对单人项目是正确取舍，且切换开关保留（配置项换回本地模型即可，口径差异已写明）；
- **换模型方案**：chunks 表带 `embedding_model` 列；换模型 = Celery 全量重嵌入 +
  双列灰度切换（新旧向量列并存，验证召回后切读、删旧列）——维度一变 HNSW 索引全废，
  这是必须预先设计的运维动作，不是"到时候再说"。

## 备选方案

- **Qdrant/Milvus**：向量能力更强，但引入双写一致性问题、独立运维面，
  租户过滤要靠 payload filter 单独实现；
- **内存向量（FAISS/numpy）**：多副本无法共享，重启重建，只适合 demo。

## 后果

- 收益：一致性免费获得（业务数据 + 向量 + 事件投影三合一），架构与运维简单；
- 代价：向量检索与业务查询共享 PG 资源（缓解：HNSW 参数调优 + 必要时独立只读副本）；
  规模天花板明确存在。

## 面试深挖点

- **何时该换独立向量库**（说明选型是权衡而非无知）：chunk 总量过千万、检索 QPS 高到
  影响业务事务、需要 GPU 加速或稀疏/多向量混合检索；迁移路径：检索模块已隔离在
  `apps/support/rag/retrieve.py`，换实现不动调用方；
- HNSW vs IVFFlat：HNSW 查询快、建索引慢、内存高；读多写少选 HNSW；
- "带 WHERE 的 HNSW 召回怎么保证"：iterative_scan / 小租户精确扫描——两层表述背熟；
- "召回率怎么验证"：M3 种子评测集含检索质量子集（标注 query → 应命中 chunk）。
