### 4.1 交付①：中断-恢复逐事件一致（CI 强断言）

**等价断言的统一算法**（三形态共用；编号步骤）：

1. 取一份多轮 cassette（含 ≥1 次工具调用 + 最终文本回复；优先复用 M2.11 手写用例，无合适者本步新增
   `tests/cassettes/recovery_baseline.json`——格式按 M2.6，名字以 M2.6 计划为准）；
2. **参照流**：session_R 上用 FakeGateway 完整跑 `AgentRuntime.run` 至 `loop_terminated`，
   从 events 表按 seq 读全序列 `E_ref`；
3. **中断流**：session_X 上同 cassette 跑，但 EventWriter 外包一层 `CrashSink`（见下），
   在第 N 次 append 调用前抛 `SimulatedCrash`；捕获后确认 events 表恰有 N−1 条已提交事件（中断确定性自检）；
4. **恢复**：对 session_X 调 M2.9 恢复单入口（【开工核对】C3 实名；FakeGateway 续跑偏移按 C2 核对结果构造），
   跑至 `loop_terminated`，读全序列 `E_x`；
5. **比较**：`normalize_events(E_ref) == normalize_events(E_x)`（实名按 C1）——归一化含 C31 豁免字段剔除 +
   §3.2-5 半截步折叠 + §3.2-6 id 引用重写；不等时输出**首个分歧点**（索引 + 两侧事件摘要），响亮失配。

`CrashSink` 形状（≤15 行伪代码，实现细节届时定）：

```python
class SimulatedCrash(RuntimeError): ...

class CrashSink:  # EventSink 协议同款形状（executor.py:44-57）
    def __init__(self, inner: EventWriter, crash_before_append_no: int) -> None: ...
    # session_id / run_id 两个 property 直通 inner
    async def append(self, event_type, payload):
        self._n += 1
        if self._n == self._crash_before:
            raise SimulatedCrash(f"确定性中断：第 {self._n} 次 append 前")
        return await self._inner.append(event_type, payload)
```

注入方式【开工核对】：AgentLoop 如何拿到 EventWriter（M2.7 构造路径）决定包装点——若 loop 内部 `EventWriter.open`，
则测试经依赖注入缝隙（工厂参数/可注入构造器）包装；若无缝隙，这是 M2.7 的可测性偏差，报用户回改，不在本步打洞。

**三形态注入点**（N 的选取按参照流实测事件序列定，测试内用"数事件类型"而非硬编码魔数）：

| 形态 | 中断点定义 | 恢复语义验证点 |
|---|---|---|
| A 工具后中断 | 第一个 `tool_result` 已提交后、下一事件前（N = tool_result 的序号 +1） | 恢复不重执行工具（凭幂等键：tool_invocations 中该 event_id 仍只 1 行、工具计数器不 +1） |
| B LLM 中断 | `llm_call` 已提交、对应 `llm_result` 前 | 半截 llm_call 作废重发（03:149-151）；折叠后与参照流一致 |
| C 审批挂起恢复 | 非崩溃：写工具命中 risk_policy → `approval_requested` → run_state=awaiting_approval 自然挂起 | `ApprovalStore.decide(...)`（store.py:425）翻转后走恢复单入口续跑；断言见 §5 |

形态 C 无"不中断参照流"（审批必然挂起），改用**双跑确定性断言**：同一 cassette 两个 session 各跑一遍
完整挂起→批准→恢复流，两条归一化序列逐事件相等；另加事件类型序列快照断言（结构不漂移）。
注：`approval_requested` payload 的 `expires_at` 已列入 C31 归一化豁免（m2.6 §3.3，交接方定案）——
两跑墙钟不同不致失配，无需在本步测试侧另做豁免。

## §7 陷阱与常见错误（症状 → 原因 → 正解）

1. **`await runtime.run(...)` 直接炸** → `run` 是 async 生成器不是协程（runtime.py:39-45） → 用 `async for ev in runtime.run(...)`。
2. **`await gateway.complete(req)` 报 TypeError/漏 await 警告** → `GatewayLike.complete` 是 `def` 返回 AsyncGenerator（runtime.py:30） → 直接 `async for chunk in gateway.complete(req)`。
3. **PowerShell 落盘的报告 git diff 是二进制/乱码** → Windows PowerShell 5.1 `Tee-Object` 默认 UTF-16、管道按 GBK 解码（06 §4 第三坑） → 报告一律 `脚本 | Out-File -Encoding utf8 reports\xxx.txt`；会话先设 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8; $env:PYTHONUTF8="1"`。
4. **报告/夹具落到了奇怪目录** → 脚本用相对路径依赖 cwd（PyCharm cwd=脚本目录，记忆教训） → `ROOT = Path(__file__).resolve().parents[1]`，一切落盘 `ROOT / "reports" / ...`。
5. **等价断言偶发红：payload 差在 `latency_ms`/事件 id** → 裸 `==` 比较未走归一化；`latency_ms` 是 C31 明示豁免字段（executor.py 写入 tool_result payload） → 只经 M2.6 归一化函数比较，测试里禁止手写字段白名单第二份（单一事实源）。
6. **形态 B 恒红：恢复流多一条 llm_call** → 半截 llm_call 作废重发是设计行为（03:149-151） → 应用 §3.2-5 折叠规则；若 M2.6 规范已定义折叠，用它的，不自造第二套。
7. **中断用 `task.cancel()` 后测试时红时绿** → cancel 落点非确定（可能落在 DB 事务/退避 sleep 内） → 用 CrashSink 在第 N 次 append 前抛异常（§4.1），确定性由 `test_crash_sink_is_deterministic` 自证。
8. **恢复段 cassette 匹配失败（响亮失配）** → FakeGateway 道内序号从 0 重计，而会话已消费 k 条（C10 本意就是让错位炸响） → 按 §0 C2 核对的续跑偏移机制构造恢复段网关；这不是 bug 是防静默错配的设计。
9. **冒烟脚本被 pytest 收集/CI 里跑出真实调用** → 文件名或位置错（test_ 前缀 / 放进 tests/） → 真实调用只许在 scripts/，且脚本名不带 test_；红线出处 00 §6.0。
10. **冒烟断言"回答里必须包含 XX"偶发失败** → 真实模型输出非确定，断文本=断质量，越了"只断不变量"的界（00 §6.2 第 3 项） → 只断三不变量 + 成本顶；文本仅打印留档。
11. **把降级演示写成 pytest 用例** → 时序敏感断言进 CI 腐蚀"红=有 bug"信号（00 §2.2 测试纪律） → 降级两条只做脚本+实录；CI 侧等价能力已由 test_event_store/交付①覆盖。
12. **停 Redis 演示里锁"看似都拿到了"** → 自造 Redis 客户端用默认重试（redis-py 8 默认 retries=10+指数退避）或 advisory lock 用了连接池连接（还池即释放） → 只复用 `core/locks.py`（M2.9 交付，含快速失败客户端与专用连接语义），演示脚本不得自己 new Redis/自己发 `pg_advisory_lock`。
13. **停 PG 演示后测试库残留脏数据** → 演示脚本走真实 commit（不在 SAVEPOINT 夹具内） → 演示用一次性 session_id 前缀（如 `demo-`），实录后可 `DELETE WHERE session_id LIKE 'demo-%'` 或直接留着（无唯一约束冲突风险，seq 作用域是会话内）。
