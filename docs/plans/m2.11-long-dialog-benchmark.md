## §1 目标与定位

- **做什么**：① 写一次性真实调用脚本 `scripts/record_long_dialog.py`，录制 30–40 轮长对话 cassette
  （M2.6 Recorder 消费，预算上限写死进脚本）；② 把它变成回放驱动的 CI 验收资产——触发 ≥2 次滚动摘要
  且第 1–5 轮埋点事实可召回（00 §6.2 第 4 条）；③ 落盘"M2 基准会话集构成登记表"，把 04"录制基准会话集"
  （04:78-79）收窄为：真实长对话 ×1 + 各终止原因/工具序列手写 cassette 清单，L3 用例显式归 M3.11（00:229）。
- **为什么**：滚动摘要（M2.5）是全 M2 唯一"没有确定性判据"的能力——压缩后信息是否还够用，只能靠
  真实模型 + 真实压缩链路端到端证明一次，然后把凭证钉进零 token 的 CI 回放（回放测行为、离线评测测质量，
  03:198）。这份 cassette 同时是 M4.3 CI 回归的三类输入之一（00:319）。
- **架构位置**：本步**不新增运行时能力**（`aegis/` 包零改动预期），是对 M2.5+M2.6+M2.7 的组合验收资产。
  任何"顺手改 runtime"的冲动都越权——发现 runtime 缺陷时停下报给用户，按缺陷单独立步处理。
- **面试叙事**：上下文压缩丢信息怎么办（00:244-245 考点）——摘要服务 prompt、events 原文兜底，
  而本步给出第三句：**压缩后召回可机器验收**。
- **规模 M = 3 次交付**：交付① 脚本 + 剧本（生产代码待遇，用户敲）→ 交付② 用户执行真实录制、
  cassette 与凭证入库 → 交付③ 回放验收测试（AI 直写）+ 登记表。

```python
async def spend_of(sf, session_id: str) -> tuple[int, Decimal, int]   # 裸 SQL：sum(prompt+completion), sum(cost), count(*)
def check_recall(transcript: dict[int, str]) -> list[str]  # 轮号→assistant 全文；返回未命中探针清单（空=全过）
def scan_secrets(blob: str) -> None                        # 断言序列化后无 "sk-" 模式与 key 明文（复用 M2.6 过滤后的双保险）
async def main() -> None
```

`main()` 编号算法步骤（伪代码 ≤15 行，唯一允许的伪代码点）：

```
1  os.environ["CACHE_TTL_SECONDS"] = "0"（在任何 aegis import 之前，D9）
2  preflight()
3  gateway = build_gateway(); rec = Recorder(gateway, ...)      # API 按 replay.py 实况【开工核对】
4  runtime = 按 M2.7 落地方式组装(rec)                            # 摘要钩子源自 rec.scoped("summary")
5  ensure_session_row(...)（若需要）
6  for i, user_input in enumerate(TURNS, 1):
7      async for ev in runtime.run(spec, SESSION_ID, user_input):
8          按 ev.type 计数；SUMMARY_UPDATED 记覆盖范围；ASSISTANT_MESSAGE 存 transcript[i]
9      tokens, cost, calls = await spend_of(...)
10     任一超限（D5 三常量）→ 打印已花费与超限项，不落盘，SystemExit(1)
11 自检（D8）：summary_updated≥2 且末次覆盖含第5轮 且 check_recall()==[]，否则不落盘 exit 1
12 scan_secrets(对 rec.cassette() 的 dump 结果序列化文本扫描)   # 落盘前扫密（Cassette.dump()，m2.6 §4.1）
13 rec.save(CASSETTE_PATH)   # M2.6 落盘函数：固定键序 + ensure_ascii=False/indent=2 + 同目录 .tmp/os.replace 原子写——脚本不自带 json.dumps
14 REPORT_PATH.write_text(报告, encoding="utf-8")；打印两个落盘路径
```

**关键不变量**：
- I1 落盘的 cassette 必然满足验收（自检先于落盘，D8）——CI 断言与录制自检是同一套判据的两次执行；
- I2 cassette 与 reports 凭证同源同次录制（同一 SESSION_ID 写进两个文件头部）；
- I3 脚本任何失败路径都不留半截 cassette（写文件是最后一步，且写前扫密）；
- I4 每轮 `runtime.run` 消费到自然终止，且每轮终止原因必须是 `completed`（出现任何闸门终止 = 剧本或
  运行时有问题，自检失败）。

## §7 陷阱与常见错误（症状 → 原因 → 正解）

1. **PowerShell 中文乱码**（06 §4 第 3 条，M2.0 实测踩过）：脚本控制台输出/管道落盘全是乱码或
  git 把凭证当二进制 → 中文 Windows `[Console]::OutputEncoding` 默认 GBK；Windows PowerShell 5.1 的
  `Tee-Object` 落盘 UTF-16 → 脚本内所有文件写入显式 `encoding="utf-8"`（本计划 §4.1 已内建，凭证
  不靠管道落盘）；控制台侧 `$PROFILE` 钉 `[Console]::OutputEncoding = UTF8` + `$env:PYTHONUTF8="1"`；
  手工 tee 一律 `Out-File -Encoding utf8` 或直接换 pwsh 7。
2. **从 scripts/ 目录运行脚本，.env 没生效**：报 `AuthError: API key 未配置` → `Settings` 的
  `env_file=".env"` 相对 **cwd** 解析（config.py:12） → 一律仓库根 `uv run python scripts/record_long_dialog.py`；
  PyCharm 运行配置 working directory 改仓库根（记忆教训同族：PyCharm 默认 cwd=脚本目录）。
3. **重录撞旧事件流**：第 1 轮就抛 `EventWriteFenced` 或 seq 从奇怪数字接续 → 复用了上次录制的
  session_id，`uq_events_session_seq`（store.py:98）+ `EventWriter.open` 接续语义（store.py:336） →
  D10：每次运行生成新 SESSION_ID，绝不写死复用。
4. **摘要一次都没触发，cassette 却存了**：CI 断言直接红或被放水 → 剧本每轮太短，history 顶不破
  4_000 预算（spec.py:94），或 M2.5"接近阈值"比例比预想保守 → D8 自检先于落盘；调法是加长每轮
  台词或加轮数，**不许去调 ContextConfig 预算**（那是在改被测物）。
5. **金额上限形同虚设**：花费显示 ¥0 但调用一直在跑 → 上游偶发缺 usage 时适配器合成 0 token
  UsageChunk（openai_compat.py:144），账本如实记 0 → D5 的 `MAX_LLM_CALLS` 第三道
  兜底按**调用行数**封顶，行数不依赖 usage 可信。
6. **把真实录制跑进 pytest**：CI 偶发红/账单异常 → 违反 00 §6.0 红线（测试与 CI 全程零真实调用） →
  录制只活在 scripts/，测试只装载 cassette；验收清单"断网跑一次"检查项就是抓这个。
7. **凭记忆发明 Recorder/FakeGateway API**：mypy 红或运行时 AttributeError → M2.6 的 API 是交接后
  才落地的代码，任何记忆版本都不可信 → 写脚本前 Read `aegis/runtime/replay.py` 全文（§0 #2），
  签名逐个抄，不确定就停下问。
8. **越权顺手做**：录制时觉得"顺手把 L3 隔离用例也录了"/"顺手给 runtime 加个便利参数" →
  L3 用例归 M3.11（00:229 明文），runtime 零改动是本步验收项（§6 末条）→ 发现缺口登记给用户，
  不动手。
9. **埋点事实用可改写措辞**：录制自检通过、日后重录换个模型就召回失败 → 埋点写成了可同义转述的
  叙述（"住在杭州西边"），模型换说法关键词就丢 → D6 三性质：高熵编号/数字串才有资格当埋点。
10. **探针答案来自原文窗口不是摘要**：召回全过但什么都没证明 → 探针轮太早，第 1–5 轮原文还在
  "近 N 轮"窗口里 → D4/D8：探针放 36–40 轮，自检"末次摘要覆盖含第 5 轮"必须过。
11. **收集数错报**（M2.4 曾错报 12 实为 11，00 §6.3 偏差登记）：预告"+8"实收不符 → 没逐项点名就报
  总数 → §6 对账法：先列出新文件内每个测试名，数完再对 pytest 收集数。
12. **交付正文被工具调用吞掉**（记忆教训，M2.3 生产代码整段蒸发）：用户看不到脚本代码 →
  工具调用之间的文本不渲染 → 交付①的完整代码必须放在回合最末、所有工具调用之后的最终消息里。
13. **cassette JSON 不可 diff**：M4.3 重录 PR 的 diff 是一行天书 → 脚本绕过 M2.6 落盘函数自带
  json.dumps（缩进/键序/ensure_ascii 口径与库内资产不一致） → §4.1 第 13 步：一律 `rec.save(...)`
  ——M2.6 `Cassette.save` 已内建 `ensure_ascii=False` + `indent=2` + 固定键序 + 原子落盘
  （m2.6 §4.1/D11），脚本不重复实现序列化。
