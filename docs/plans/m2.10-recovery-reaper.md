## §1 目标与定位

**做什么**：把 03 §5"恢复调度三件套"的最后两件接上电——**租约续租**（运行中 loop 周期性对
`sessions.lease_expires_at` 续租）与 **reaper**（Celery beat 周期任务扫描"租约过期且
run_state=running"→ CAS 抢租 → 触发恢复）；同时把**两类恢复语义**（半截工具调用 / 半截 LLM
调用，03:146–151）与**恢复次数上限 C9**（超限置 `run_state=failed` + 审计事件，failed 的进入
路径在此闭合——store.py:42 注释预告）落成代码。第三件（"先取会话锁再恢复"单入口）M2.9 已交付，
本步**复用不重造**。

**为什么**：kill -9 / 发布重启（crash-only，02 §5 落档段）后，崩溃的 run 必须有人"发现并认领"
（03:153）；而毒会话不能让 reaper 无限抢租→恢复→再崩（C9，00:228）。

**面试叙事位置**（00 §6.2 面试考点原文）："恢复由谁调度（租约/reaper/锁单入口三件分开答）"；
03:161–162："HITL 挂起是'计划内恢复'：审批后的恢复路径与崩溃恢复是同一条代码路径——
**日常流量天天在测灾难恢复逻辑**"。本步交付后这句话才为真。

**范围（以 00:228 为权威，防越步）**：

| 做 | 不做（弱模型高危越步点） |
|---|---|
| loop 周期续租 + 续租失败自毁（C2 协议一接行为） | ~~审批到期扫描调度~~——`ApprovalStore.expire_due` 的 reaper 定时触发归 **M3.9**（store.py:459 docstring 与 ix_approvals_expiry 注释 store.py:151–152 双双写明） |

### 3.2 本步定案（蓝图未覆盖、有唯一合理答案，已定并给理由）

1. **`LeaseStore` 落 `aegis/runtime/store.py`**：租约是 sessions 一张表的真相，与 `ApprovalStore`
   同款"CAS 原语层、事件与 run_state 编排不在此层"的分工（store.py:390–396 先例）；不新开文件，
   五表真相集中一处，migrations/env.py 的模型注册（env.py:10）也无需增行。
2. **半截工具调用的统一算法：复用原 tool_call 事件 id 重执行，以原 id 写 tool_result/tool_error 闭合**。
   write-ahead 事件已存在，恢复期**绝不产生第二个 tool_call 事件**——否则同一逻辑调用两把幂等键，
   下游去重当场失效（与 X1 同族错误，executor.py:188–189 的镜像）。读/写的分野在**安全性论证**而非
   机制：读的安全来自无副作用（X2 机器判定），写的安全来自原幂等键透传下游去重（03:147–148）。
   03 与 X2 的表述张力（03 说"安全重发"不分读写、00:221/X2 说"仅读可重发"）以此统一——两句说的
   是同一件事的两半，登记进文末上游问题清单，03 §5 措辞毕业时补一句。M2 下游去重是假的
   （00 §10.1 #6，M3.7 闭环），测试用"按 ctx.tool_call_id 记账的假下游"自证键复用。
3. **C9 审计事件 = 新增事件类型（实况基数 +1：写作时点 14→15；若 M2.8 D6 `guardrail_triggered` 获准
   则 15→16——以开工时 events.py 实况数为基数，§0#10）**，建议值 `EventType.RECOVERY_ABANDONED =
   "recovery_abandoned"`——值本身**终值待 P4 拍板留档**，"需要新事件类型"是本条定案的机制性结论。
   既有 14 类无一可承载：`loop_terminated` 的 payload 契约是终止原因枚举——03:139 写"对应 §2 的
   7 类枚举"，但按信任序以代码为准：`TerminationReason` 实有 **8 成员**（7 类终止条件 + 七类之外的
   `gateway_rejected`，均可出现在 loop_terminated payload——spec.py:21–37 docstring 与 00:108 明言），
   恢复分支**不得按"7 类"白名单校验 reason**（会误拒 gateway_rejected 事件；03 旧表述登记文末
   上游问题清单 #7）；而"恢复放弃"时根本没有 loop 在跑，且给 `TerminationReason` 加成员会打破 `TERMINATION_GATES`
   len==6 的六道闸门口径（spec.py:40–45）。加成员走既定机制：先让 test_events.py:13 的值快照红、
   过口径再改（events.py:23 注释明文允许此流程）。无投影（审计类，与审批四事件同列
   ——store.py:272–273"查不到 = 该事件无投影"）。payload：`{"recovery_count": int,
   "recovery_limit": int, "last_lease_owner": str | None}`。
4. **recovery_count 语义 = 连续崩溃恢复计数**：reaper `steal_expired` 成功时 +1；干净 `release`
   （正常终止/挂起）时**清零**。不清零则长寿会话攒满 3 次历史崩溃后永久 failed——计数器要堵的是
   "毒会话崩溃循环"（00:228 原文），任何一次干净收尾都证明会话不是毒的。
5. **上限建议取 3，终值待 P3 拍板**：00:228 写"（如 3 次）"是示例值；本条定案的是**配置化**
   （`Settings.recovery_limit`）与语义：以 3 为例，第 1–3 次过期可被抢租恢复，第 4 次发现过期时置 failed。
6. **调度参数进 `Settings`**（config.py 既有"演示值"惯例，如 provider_rate 注释）：
   `lease_ttl_s / lease_renew_interval_s / reaper_interval_s / recovery_limit`——数值见 3.3。
7. **celery task 是薄同步壳，async 核心可直测**：`reap_once` 是纯 async 函数（依赖全注入），
   `@celery_app.task` 壳只做 `asyncio.run(...)`——测试零 broker 依赖，符合"CI 零真实调用/
   时序断言不进 CI"纪律。
8. **worker 内每次任务用 NullPool 独立引擎**：`asyncio.run` 每次新建事件循环，而 asyncpg 连接
   绑定创建时的循环——复用 `aegis.core.db.get_engine()` 的全局池会跨循环报错（§7 陷阱 2）。
   最小引导下每次 `create_async_engine(url, poolclass=NullPool)` + finally `dispose()`。
9. **broker = `Settings.redis_url`，无 result backend**：reaper 任务 fire-and-forget
   （`task_ignore_result=True`），结果进日志与事件流，不需要 backend（少一个 Redis 键面）。
10. **import-linter layers 插入 `aegis.workers`**：置于 `aegis.apps` 与 `aegis.runtime` 之间——
    workers 消费 runtime（恢复入口）与 core（配置），不许反向；apps（M3.8）可 import workers
    注册钩子。不列入则 workers 完全不受分层约束，静默腐蚀。pyproject.toml:52–60 的 layers 列表
    加一行即可。
11. **恢复钩子注入而非 import 业务**：`ResumeHook = Callable[[str, str, int], Awaitable[None]]`
    （session_id, lease_owner, lease_generation）。AgentSpec 由 L3 注入（03 §1），M2 没有 L3——
    reaper 不可能自己装配 spec。模块级 `register_resume_hook()`，M3.8 注册真实钩子；M2 测试与
    kill -9 脚本注入演示钩子。**未注册钩子时 reaper 只抢租不恢复**（日志警告）：该会话租约再次
    过期会被再抢，recovery_count 递增，最终 C9 置 failed——行为自洽、不悬空。
12. **lease owner 串 = `f"{主机名}:{pid}"`**（`default_lease_owner()` 辅助函数）：03:154
    "lease_owner = 副本 id"；主机名+pid 在 compose 多副本与本地进程两种形态下都唯一且可读。

### 4.2 store.py：LeaseLost + LeaseStore（交付①）

```python
class LeaseLost(RuntimeError):
    """租约旁落（C2 协议一）：续租/释放 CAS 打空——所有权已被 reaper 转移。
    终态，绝不退避重试；当前 loop 立即自毁，不再写任何事件。"""

def default_lease_owner() -> str: ...
    # f"{socket.gethostname()}:{os.getpid()}"——03 §5"lease_owner = 副本 id"

class LeaseStore:
    def __init__(self, factory: SessionFactory) -> None: ...
    async def acquire(self, session_id: str, *, owner: str, ttl_s: float,
                      now: datetime | None = None) -> int | None: ...
    async def renew(self, session_id: str, *, owner: str, generation: int,
                    ttl_s: float) -> bool: ...
    async def release(self, session_id: str, *, owner: str, generation: int) -> bool: ...
        # 只清租约列，不碰 run_state（交接方定案，开工可复核）——置位归 SessionStateStore.transition
    async def steal_expired(self, session_id: str, *, owner: str, ttl_s: float,
                            recovery_limit: int, now: datetime | None = None) -> int | None: ...
    async def mark_failed(self, session_id: str, *, recovery_limit: int,
                          now: datetime | None = None) -> bool: ...
    async def list_expired(self, *, now: datetime | None = None, limit: int = 100) -> list[str]: ...
```

全部方法一条原子 UPDATE/SELECT，CAS 风格与 ApprovalStore 完全同款（条件进 WHERE、输赢看
rowcount/RETURNING）；`now` 可注入落回 `func.now()`（store.py:464 先例）。逐方法算法：

**acquire**（run 起点，正常路径与恢复单入口共用；交接方定案，开工可复核）：
1. `UPDATE sessions SET lease_owner=:owner, lease_expires_at=<now>+ttl,
   lease_generation=lease_generation+1
   WHERE id=:sid AND run_state = 'running'
   AND (lease_owner IS NULL OR lease_expires_at <= <now>)
   RETURNING lease_generation`——**SET 不碰 run_state**：LeaseStore 只管租约列，
   `run_state='running'` 是 WHERE 前置条件，调用方须先经 `SessionStateStore.transition`
   完成 T1/T3（idle/awaiting_approval→running，m2.9 §4.4）再 acquire；
2. 拿到行 → 返回新 generation；打空 → 返回 `None`（活租约在别人手里、run_state 非 running，或行不存在——K5）。

**renew**：`UPDATE ... SET lease_expires_at=<now>+ttl WHERE id=:sid AND lease_owner=:owner
AND lease_generation=:generation` → `rowcount == 1`。打空即围栏信号（协议二：**不重试**）。

**release**（交接方定案，开工可复核）：`UPDATE ... SET lease_owner=NULL, lease_expires_at=NULL,
recovery_count=0 WHERE id=:sid AND lease_owner=:owner AND lease_generation=:generation`
→ `rowcount == 1`。**只清租约列**（recovery_count 清零 = 决策 3.2#4），不碰 run_state——
终止/挂起的置位由调用方以相邻调用走 M2.9 既有 `SessionStateStore.transition`（T4/T2）。
打空返回 False（调用方抛 LeaseLost）。

**steal_expired**（reaper 专用）：
1. `UPDATE ... SET lease_owner=:owner, lease_expires_at=<now>+ttl,
   lease_generation=lease_generation+1, recovery_count=recovery_count+1
   WHERE id=:sid AND run_state='running' AND lease_expires_at <= <now>
   AND recovery_count < :recovery_limit RETURNING lease_generation`；
2. 赢家恰一个（两个 reaper 赛跑输家打空拿 None）；
3. SET 不碰 run_state——**抢租不构成状态翻转（running→running）**，m2.9 §4.4 迁移表无例外条目
   （交接方定案，开工可复核）。

**mark_failed**（C9 终局；交接方定案，开工可复核）——run_state 翻转不留在 LeaseStore，两步走：
① lease 侧 CAS 判赢家：`UPDATE ... SET lease_owner=NULL, lease_expires_at=NULL
WHERE id=:sid AND run_state='running' AND lease_expires_at <= <now>
AND recovery_count >= :recovery_limit` → `rowcount == 1`（赢家恰一个）；
② 赢家在同事务/相邻调用经 `SessionStateStore.transition(session_id, expected=RUNNING, to=FAILED)`
完成 T5 翻转（m2.9 §4.4），随后写审计事件（恰一次）。

**list_expired**：`SELECT id FROM sessions WHERE run_state='running' AND
lease_expires_at <= <now> ORDER BY lease_expires_at LIMIT :limit`（走 ix_sessions_reaper）。

**关键不变量**：
- **LeaseStore 全部方法的 SET 子句不碰 run_state**——run_state 的唯一置位路径是
  `SessionStateStore.transition`（m2.9 §4.4 迁移表；交接方定案，开工可复核）；
- generation 只增不减（acquire/steal 都 +1）；同一 (owner, generation) 二元组是一次 run 的
  完整生命周期凭据；
- 过期时间的写与比全部用同一口 DB 钟（`func.now()`），应用侧时钟零参与；
- `<now>+ttl` 的 SQL 表达：首选 `func.now() + timedelta(seconds=ttl_s)`（SQLAlchemy 编译为
  interval 绑定参数，asyncpg 支持 timedelta）；若绑参报错回退 `func.make_interval(0,0,0,0,0,0,ttl_s)`
  ——两种都不许用 Python `datetime.now()` 拼（时钟漂移）。

### 4.3 loop.py：续租接电与自毁（交付①，修改点随 K1/K3/K4 实况）

2. **续租后台任务**（≤15 行伪代码上限内）：

```
async def _renew_lease_forever(leases, session_id, *, owner, generation,
                               ttl_s, interval_s, sleep=asyncio.sleep) -> None:
    while True:
        await sleep(interval_s)
        if not await leases.renew(session_id, owner=owner,
                                  generation=generation, ttl_s=ttl_s):
            raise LeaseLost(f"session={session_id} gen={generation} 续租打空——所有权旁落")
```

   与主循环并发持有（K3：建议独立 task，主循环退出时 cancel）；`sleep` 可注入（同

3. **LeaseLost / EventWriteFenced 同一处置分支**：立即自毁——取消当前步、**不写任何进一步事件**

   向上传播；恢复交给持有新租约的一方；
4. **终止路径**：正常完成/挂起时先由 M2.9 既有路径 `transition` 置位（T4→IDLE / T2→AWAITING_APPROVAL），
   再 `await leases.release(session_id, owner=..., generation=...)`——release 只清租约列、不碰
   run_state（K4/交接方定案，开工可复核）；
   release 返回 False → 同 LeaseLost 处置（事件与置位已由前序完成，仅放弃清租约列，日志留痕）。

### 4.4 loop.py：两类恢复语义（交付②，扩展 M2.9 单入口）

**泛化签名定死（交接方定案，开工可复核）**：`resume(spec, session_id, approval_id: str | None = None)`
——`approval_id` 非 None 走 M2.9 审批分诊（其 §4.3d 算法）；**None 走本节崩溃恢复分诊**；两分支共享
"取锁→分诊→续跑"内部路径（已回写 m2.9 §2.2 提供物行与 §4.3d、m2.12 §0 C3）。

恢复分支（approval_id=None）在单入口"已持会话锁 + 已 acquire 租约（或 reaper 已 steal）"之后执行。算法：

1. **读事实**：`SELECT * FROM events WHERE session_id=:sid ORDER BY seq ASC`；逐条按
   `schema_version` 路由解析——当前仅 v1 一个解析器，`schema_version != 1` 直接 raise
   （留路由点不留死代码，events.py:17–18）；
2. **扫描配对**：维护 `open_tool_calls: dict[event_id, payload]`——遇 `tool_call` 记入，遇
   `tool_result`/`tool_error` 按 `payload["tool_call_id"]` 移除（键契约：executor.py:158–164 写
   tool_call 含 `tool_name`/`args`，tool_result/tool_error 含 `tool_call_id`——store.py:226–233
   投影同键，机器强制）；同时记录最后一个 `llm_call` 之后是否出现 `llm_result`（配对键 K2）；
   记录最后事件类型；
3. **分情况**（按序判定，最多命中一支）：
   a. 最后事件是 `loop_terminated` → 上一 run 其实已收尾、只是 run_state 没置回——**仅修状态**：
      `release(run_state=IDLE)`，不跑循环；
   b. 存在悬挂 tool_call（正常情况至多一个——单写者顺序执行；>1 视为数据异常 raise）→
      **凭原事件 id 重执行**：从当前 `AgentSpec.tools` 查 `ToolDef`；
      - 工具已不在 spec → 写 `tool_error`（payload 含原 `tool_call_id`、error="恢复期工具缺失"）
        闭合投影，错误作为观察结果回填模型，进循环；
      - `side_effect is READ` → 直接重执行（无副作用，重跑无害）；
      - `side_effect is WRITE` → 同样重执行，但**幂等键必须是原 tool_call 事件 id**
        （`ToolContext(tool_call_id=原事件id)`），下游按键去重——已执行返原结果、未执行正常执行
        （03:147–148）；
      - 两种都**不再写新 tool_call 事件**（write-ahead 已存在，决策 3.2#2）；成果以原
        `tool_call_id` 写 `tool_result`/`tool_error`（投影 `_finish_invocation` 恰好闭合原行，
        store.py:226–233）；然后回到主循环下一轮；
      - 实现注意：此路径绕过 `ToolExecutor.execute` 的 write-ahead 步（executor.py:158），
        需要执行器暴露"以既有 tool_call_id 执行"的窄入口——建议
        `ToolExecutor` 增方法 `async def reexecute(self, name: str, args: Mapping[str, Any],
        *, tool_call_id: str) -> ToolOutcome`（复用 ⑤⑥⑦ 步，跳过 ①–④；args 已是当年校验过的
        快照，从事件 payload 取，不再过 pydantic——事实源里的参数不需要再"不信"）；
   c. 存在悬挂 `llm_call` → **作废重发**：不为旧调用补任何事件，循环从"组装上下文"重新开始，
      新 `llm_call` 事件自然产生；显式接受重生成文本不同（03:149–151，前端重置帧是 M3.10 的事）；
   d. 都没有（如崩在两步之间的干净缝上）→ 直接从"组装上下文"续跑；
4. **新 run**：恢复出的循环用**新 run_id**（uuid4().hex，X5），`EventWriter.open` 接续旧 seq
   （store.py:329–336）。

**关键不变量**：恢复期同一逻辑工具调用**恰一个**幂等键（原事件 id）；每个 tool_call 的终局
恰一个（tool_result | tool_error）；重放只读 events 不读投影（投影可由事件重建，方向不可反）；
恢复路径产出的事件流必须能通过 M2.6 的事件等价性归一化断言（M2.12 消费）。

### 4.6 workers/reaper.py（交付③）

```python
ResumeHook = Callable[[str, str, int], Awaitable[None]]
# (session_id, lease_owner, lease_generation)——钩子实现负责装配 spec 并调 M2.9 单入口续跑

@dataclass(frozen=True, slots=True)
class ReapReport:
    scanned: int
    recovered: tuple[str, ...]     # 抢租成功（含未注册钩子只抢未恢复的）
    abandoned: tuple[str, ...]     # C9 超限置 failed

def register_resume_hook(hook: ResumeHook) -> None: ...   # M3.8 注册；测试注入
def default_lease_owner 复用 store.py（不重复实现）

async def reap_once(
    factory: SessionFactory,
    *,
    owner: str,
    lease_ttl_s: float,
    recovery_limit: int,
    resume: ResumeHook | None = None,
    now: datetime | None = None,
) -> ReapReport: ...

@celery_app.task(name="aegis.workers.reaper.reap_expired_leases")
def reap_expired_leases() -> dict[str, int]: ...   # 薄同步壳：asyncio.run(_reap_fresh())
```

**reap_once 算法**：
1. `ids = await LeaseStore(factory).list_expired(now=now)`；
2. 逐个 `gen = await leases.steal_expired(sid, owner=owner, ttl_s=lease_ttl_s,
   recovery_limit=recovery_limit, now=now)`；
3. `gen` 拿到 → 记入 recovered；有 resume 钩子则 `await resume(sid, owner, gen)`（钩子内部走
   M2.9 单入口：取会话锁 → §4.4 恢复分支）；钩子抛异常按 **P6 裁决**处置（建议：捕获记日志，
   继续下一会话）；无钩子 → 日志警告"抢租未恢复，等待下轮/超限"
   （行为自洽性见决策 3.2#11）；
4. `gen is None` →（可能被并发赢家拿走，也可能超限）`await leases.mark_failed(sid,
   recovery_limit=recovery_limit, now=now)`；返回 True 的**赢家**按 §4.2 mark_failed ② 经
   `SessionStateStore.transition(expected=RUNNING, to=FAILED)` 完成 T5 翻转后写审计事件：
   `w = await EventWriter.open(factory, sid, run_id=uuid.uuid4().hex)` →
   `await w.append(EventType.RECOVERY_ABANDONED, {"recovery_count": recovery_limit,
   "recovery_limit": recovery_limit, "last_lease_owner": ...})`；记入 abandoned；
   两个 CAS 都打空 → 跳过（别的 reaper 赢了）；
5. 返回 `ReapReport`。

**_reap_fresh（同步壳的 async 内胆）**：`create_async_engine(get_settings().database_url,
poolclass=NullPool)` → `async_sessionmaker(engine, expire_on_commit=False)` → `try: reap_once(...,
owner=default_lease_owner(), 参数取 get_settings()) finally: await engine.dispose()`（§7 陷阱 2）。

**关键不变量**：每次抢租赢家恰一个（CAS）；mark_failed 赢家恰一个 → 审计事件恰一条；
先翻 failed 再写事件（崩在缝上 = failed 无审计事件，接受并在 docstring 注明——反向顺序会造出
"有放弃事件但仍 running"的谎言）；reaper 自身不 import 任何业务（apps），恢复逻辑全在钩子后面。

## §7 陷阱与常见错误（症状 → 原因 → 正解）

1. **Windows 上 worker 起不来/任务挂死** → Celery 4 起不支持 Windows prefork 池 →
   本地一律 `--pool=solo`（06 §4 第 1 坑）；生产形态以容器为准，本步不做容器（M4.7）。
2. **worker 第二次任务报 `got Future attached to a different loop` / `Event loop is closed`** →
   薄壳每次 `asyncio.run` 新建事件循环，asyncpg 连接绑定创建时的循环，复用全局
   `get_engine()` 连接池必炸 → 每次任务 `create_async_engine(url, poolclass=NullPool)` +
   `finally: await engine.dispose()`（决策 3.2#8）；**不许**改 aegis/core/db.py 的全局单例来迁就
   worker（那是 API 进程的资产）。
3. **worker 启动刷 `CPendingDeprecationWarning: broker_connection_retry ...`** → Celery 5.3+
   要求显式声明启动期重连策略 → `broker_connection_retry_on_startup=True`（§4.5 已含）。
4. **租约过期测试永远不过 / 断言 expires "变大"失败** → PG `now()` = 事务开始时间，而
   tests/conftest.py:62–65 的 db_conn 把整个测试包在**一个外层事务**里——事务内 `func.now()`
   恒定 → 过期场景直插"过去时刻"的 lease_expires_at，或用可注入 `now`（C7 先例，本步 LeaseStore
   已带）；**绝不 `sleep` 等真钟**（时序断言不进 CI，00 §2.2）。
5. **mypy 报 `import-untyped: Skipping analyzing "celery"`** → celery 无完整 py.typed →
   pyproject 加 `[[tool.mypy.overrides]] module = "celery.*"  ignore_missing_imports = true`
   （先实测再加：若当时 celery 版本已带类型则不加）。
6. **凭记忆写 Celery API（beat_schedule 键名、task 装饰器参数、`-A` 目标格式）** → 弱模型高发
   → 写前 Read `.venv/Lib/site-packages/celery/` 内源码或先跑
   `uv run celery -A aegis.workers.celery_app inspect registered` 核实；本仓库 `-A` 目标是
   **`aegis.workers.celery_app`**（06 §4 写的 `workers.app` 是规划期旧名，见文末上游问题 #2）。
7. **顺手把 `ApprovalStore.expire_due` 挂进 beat** → 03 §5 的 reaper 叙述未区分两类扫描，
   易误读 → 审批到期扫描归 **M3.9**（store.py:459、store.py:151–152 双处注明）——越步。
