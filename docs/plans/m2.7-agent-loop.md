## §1 目标与定位

- **做什么**（00 §6.1 M2.7 行，规模 L）：新建 `aegis/runtime/loop.py`（AgentLoop），把 M2.1–M2.6
  的全部部件总装成可运行的循环：组装上下文（M2.5）→ 经 main 作用域网关调 LLM → 解析三分支
  （文本 / 工具 / 协议违规）→ 工具经 ToolExecutor → 结果入上下文 → 下一轮；**7 类终止条件逐个接电**
  （正常完成 + 六道闸门）；`AgentRuntime.run()` 接线（签名定死，runtime.py:39）；含"诱导死循环"
  对抗用例；会话级 token 预算闸门接电（三级预算的 L2 一级，00 §10.1 #2）。
- **不做什么**（越界即返工）：Guardrails 实体（M2.8，本步只留三挂点）；审批单/挂起/run_state
  置位/会话锁（M2.9——闸门 #6 本步只接**取消信号**与终止处理路径）；续租/reaper/半截恢复的
  跨进程部分（M2.10）；cassette 格式与 FakeGateway 本体（M2.6 已交付，本步只消费）；
  给 `EventType`/`TerminationReason` 加成员（值快照测试钉死，改值=破坏重放）。
- **架构位置**：L2 的心脏。03 卷首："模型是租来的，Harness 才是自己的"——AgentLoop 是
  Harness 的编排中枢，对 L3 不可见（runtime.py:5–7）；面试叙事上，六道闸门 + 事件流单写者
  是"循环失控/不可观测"两大工程问题的答案（00 §1）。

### 本步定案的决策（蓝图未覆盖、有唯一合理答案，理由随附）

- **D1 `AgentRuntime.__init__` 扩参**：`run()` 签名定死（runtime.py:42），但构造器不在契约内。
  扩为 `__init__(self, gateway: GatewayLike, session_factory: SessionFactory, *, cancel_event: asyncio.Event | None = None, run_id_factory: Callable[[], str] | None = None)`。
  理由：run 需要 EventWriter（要 factory）与 run_id（X5：每次启动新生成，默认 `uuid4().hex`）；
  factory 按形状注入（store.py:168–170）测试故障注入才有缝。
- **D3 `max_tokens = spec.context_config.output_reserve`**：03 §3 预算表"余量=留给模型输出"，
  输出上限即该层预算，两处一个事实源；`deadline_s = spec.policy.llm_step_timeout_s`（C1）。
- **D4 canonical_json 规范**：`json.dumps(parsed_args, sort_keys=True, ensure_ascii=False, separators=(",", ":"))`。
  键排序=语义等价归一；`ensure_ascii=False` 与仓库既有 dumps 口径一致（executor.py:210、cache.py:40）；
  紧凑分隔符去空白噪声。`arguments_json` 解析失败（网关不解析坏参数，schema.py:29–30）时
  **以原始字符串为规范形**——坏 JSON 逐字重复也是重复。不做哈希：直接字符串比较等价且可调试
  （03:55 与 00 §6.1 M2.7 行的"哈希（窗口）"同属实现描述非行为约束——字符串直比与取哈希
  判定结果等价；对权威行措辞的这一偏离在此显式登记，另见文末上游问题 #6）。
- **D5 重复调用检测 = 连续计数器**：状态 `(last_key, streak)`，key=`(tool_name, canonical_json)`；
  相同 +1，不同重置为 1。03 阈值语义是"**连续** 3 次"（03:51），窗口长度全文未给
  （03 防脑补声明 C.7#5；00 §6.1 M2.7 行的"窗口"措辞同此消解——连续段即最小滑动窗口，
  行为等价，登记见上游问题 #6），且可回放确定。行为：streak 达
  `policy.repeat_call_limit`（=3）时**该次不执行**（不 write-ahead、无 tool_call 事件），以
  `PROMPT_REPEAT_BREAK` 作为该 tool_call 的 role="tool" 回填（打断+"换个方法"）；打断后 streak
  不清零，**下一次仍然相同 → 终止 REPEATED_CALLS**（03:51"再犯则终止"）；换了参数/工具则重置。
- **D6 幻觉工具名计入闸门 #5**：`registry.get(name) is None` 的调用是"语法上是工具调用、
  语义上非法"——归协议违规计数（00 §6.3 M2.3 行明文"处置归 M2.7 闸门 #5"）；回填文本仍用
  executor 返回的 ERROR content（既有话术点名可用工具，executor.py:118–122），loop 只负责
  违规计数 +1。
- **D7 协议违规判定与纠错**：违规 = ①无 tool_calls 且聚合文本 `strip()` 为空；②`StopChunk.reason=="tool_calls"`
  但未收到任何 ToolCallChunk；③D6 幻觉工具名。违规计数为**连续**计数（合法输出清零）；
  违规时注入 `PROMPT_PROTOCOL_RETRY` 为 **role="user"** 消息（不动 system 层——system 预算
  固定不可挤占，03 §3）进入下一轮；连续违规超过 `policy.protocol_retry_limit`（=2，即纠错 2 次
  后第 3 次仍违规）→ 终止 PROTOCOL_VIOLATION + 降级回复（03:52）。
- **D8 闸门 #3 计数口径**：累计值 = Σ(每次 main 调用的输入估算 + 输出估算)，全部用
  `estimate_tokens`（C25）；输入估算 = messages 各 content + tool_calls.arguments_json 的估算和；
  输出估算 = 聚合文本 + 各 arguments_json 的估算和。**闸门只计 main 作用域主循环调用**——
  摘要/守卫是小额辅助调用，进 usage_ledger 账单但不进闸门（闸门防主循环失控；辅助层挂了
  fail-open 走 C34）。会话级（非 run 级）语义：估算值随 `llm_call.payload["input_tokens_est"]` /
  `llm_result.payload["output_tokens_est"]` 落盘，新 run 起点 = 扫本会话既有此二键求和
  （事件即事实源，计数可重放重建，不加新列）。**检查时机 = 每次 LLM 调用前**：
  `已累计 + 本次输入估算 > policy.session_token_budget` → 终止 TOKEN_BUDGET_EXCEEDED，
  发"预算已用尽"的明确告知 assistant_message（**不静默截断**，03:50）。
- **D9 六类网关异常 → 循环分支映射矩阵**（§4.4 表）：可降级四类拆两组——
  暂时不可用（Exhausted/Overloaded）走闸门 #2 语义（步作废+降级回复+终止 step_timeout）；
  预算类（BudgetExceeded/TenantQuota）与闸门 #3 同语义（终止 token_budget_exceeded，payload
  `cause` 区分 L1/L2 层级——三级预算共用一个终止原因）；Rejected 按 C6；StreamInterrupted 见 D10。
- **D10 `GatewayStreamInterrupted` 进程内处置**：本步作废——已收 chunk 全部丢弃（不入上下文、
  不计 token），追加 `llm_result{status:"interrupted"}` 配对事件，**continue 进下一轮迭代重发**
  （03 §5"作废重发"）；不设独立重发计数器——重发消耗迭代数，`max_iterations` 天然兜底。
  **与 M2.10 的分工**：进程活着的流中断由本分支消化；进程死掉的半截 llm_call（有 call 无
  result）由 M2.10 reaper 抢租后按恢复语义作废重发——同一语义两个触发面。
- **D13 话术常量**：兜底/提示文案全部收敛为 loop.py 模块级常量（测试断言子串、M2.8 出口
  防护替换有单点）：`FALLBACK_MAX_ITERATIONS`（含"转人工"）、`FALLBACK_STEP_FAILED`、
  `FALLBACK_BUDGET`（含"预算"与"不做静默截断"语义）、`FALLBACK_REPEATED`、`FALLBACK_PROTOCOL`、
  `PROMPT_REPEAT_BREAK`（含 policy 阈值格式化）、`PROMPT_PROTOCOL_RETRY`；另有
  `_SUMMARIZE_PROMPT`（摘要指令，唯一例外：随其唯一消费者 `_make_summarizer` 落
  runtime.py 模块级——D15/§4.3）。取消不发兜底话术
  （用户主动取消无需道歉文）；GATEWAY_REJECTED 不发任何 assistant_message（C6）。
- **D14 事件不变量**：每 run 恰一条 `loop_terminated` 且必为末事件；`user_message` 必为
  首事件（见 §4.5）。
- **D15 两枚 summarize 钩子由本步组装（共用 `_make_summarizer`，两道各归其主；交接方定案，开工可复核）**：
  缝蓝图定案"摘要钩子是注入的 async 可调用，组装方负责从网关构造"。`AgentRuntime.run` 内构造**两枚**：
  ① **tool_digest 道**视图 → `ToolExecutor` 的 `summarize`（工具结果摘要，§4.2 步骤 6）；
  ② **summary 道**视图 → `ContextBuilder` 的 `summarize`（滚动摘要，§4.2 步骤 7——m2.6 D9 与
  m2.5 §2.2 钉死由组装方接线；漏接则 builder.summarize=None、滚动摘要静默失效，M2.11 验收

  人肉算术）、fail-open 分别由 executor 与 builder 各自的 C34 路径消化。伪代码见 §4.3。
  作用域获取方式以 replay.py 实况为准【开工核对 §0#4】。
- **D16 事件外流机制 `_Tap`**：run() 要"事件流形式产出所有中间步骤"，而 executor 的事件在其
  内部 append——loop.py 内建 `_Tap`（实现 EventSink 协议，包装 EventWriter：append 委托真写、
  返回的 AgentEvent 同时入 `pending: deque`）；loop 自己的 append 也走 _Tap，每个 await 点后
  drain 并 yield——**yield 顺序 ≡ seq 顺序，逐条不漏**。
- **D17 迭代计数定义**：一次 main 作用域 LLM 调用 = 一轮。纠错重试（D7）与中断重发（D10）
  均计入——`max_iterations`（=10）是一切循环形态的总兜底。精确触发：已完成 n 次调用且
  n ≥ max_iterations 时再欲发起下一次 → 终止 MAX_ITERATIONS。
- **D18 `StopChunk.reason=="max_tokens"`**：聚合文本非空 → 按文本分支完成（payload
  `stop_reason` 留痕 "max_tokens"，不算违规——截断是预算现实不是协议错误）；文本为空 → 按
  D7① 违规处理。
- **D19 user_message 由 loop 写入**（每 run 首事件）：单写者不变量下 EventWriter 归 run 独占，
  API 层（M3.2）不得旁路写事件——M3.2 行"user_message 事件落盘"届时经 run() 兑现
  （见文末上游问题 #3）。
- **D20 多工具调用**：一轮 LLM 响应含多个 ToolCallChunk 时**顺序逐个**执行（ADR-002 单
  Agent 主循环，无并行）；重复检测逐个过；中途触发终止则立即终止（剩余调用弃置，
  detail 留痕）。文本与 tool_calls 并存 → 工具分支，文本随 assistant(tool_calls) 消息入 turns。

### §4.2 `AgentRuntime.run` 编号步骤

2. 读 sessions 行取 `tenant_id`/`user_id`（P2），无行 → `ValueError`；
3. `token_seed`：SELECT 本会话 `type IN ('llm_call','llm_result')` 的事件 payload，Python 侧
   累加 `input_tokens_est`/`output_tokens_est`（缺键当 0）——D8 会话级口径；
4. `writer = await EventWriter.open(self._session_factory, session_id, run_id)`；`tap = _Tap(writer)`
   （M2.9 将在此步之前插入"先取会话锁"）；
5. `registry = ToolRegistry(spec.tools)`；
6. `executor = ToolExecutor(registry, tap, tenant_id=…, user_id=…, tenant_config=spec.tenant_config,`

   `summarize=_make_summarizer(<tool_digest 视图>, tenant_id, session_id))`
   ——**显式接线**：此前二者与 LoopPolicy/ContextConfig 靠默认值巧合相等（30.0/3_000），
   本步起改 policy 必须生效（素材包 pack-runtime 可疑点 #3）；
7. `builder = ContextBuilder(self._session_factory, tap, config=spec.context_config, tenant_id=…, user_id=…,`

9. `async for ev in loop.run(user_input): yield ev`。

### §4.3 `AgentLoop.run` 编号步骤（循环骨架，03 §2 流程图落到方法级）

1. `append(USER_MESSAGE, {"content": user_input})`；drain→yield。**首事件不变量 I5**；
2. （M2.8 挂点①位置——本步仅注释占位）；
3. 初始化：`iteration=0`；`violations=0`；`repeat_key=None, repeat_streak=0`；
   `tokens_used=token_seed`；`turns: list[Message] = []`；
4. **循环**（`while True`）：
   1. 取消检查（闸门 #6）：`cancel_event.is_set()` → `_terminate(CANCELLED, fallback=None)`，return；
   2. 轮数检查（闸门 #1）：`iteration >= policy.max_iterations` →
      `_terminate(MAX_ITERATIONS, fallback=FALLBACK_MAX_ITERATIONS)`，return；`iteration += 1`；
   3. `messages = await builder.build(system_prompt=spec.system_prompt, user_input=…, working=turns)`
      （缝蓝图签名：**async def**、keyword-only，参数名是 `working` 非 turns，`system_prompt` 必填——
      m2.5 计划 §4.2（171–177 行）；K1 开工时以 context.py 实况为准）；
   4. `input_est = _estimate_request(messages)`（各 content + 各 tool_call.arguments_json 的
      `estimate_tokens` 和）；
   5. 预算检查（闸门 #3，调用前查——不打半截请求）：`tokens_used + input_est > policy.session_token_budget`
      → `_terminate(TOKEN_BUDGET_EXCEEDED, fallback=FALLBACK_BUDGET)`，return；
   6. `append(LLM_CALL, {"iteration": iteration, "tier": spec.model_tier, "input_tokens_est": input_est})`；
   7. 构造 `LLMRequest(tier=spec.model_tier, messages=messages, tools=[ToolSpec(name=t.name,
      description=t.description, parameters=dict(t.parameters_schema)) for t in spec.tools],
      tenant_id=…, session_id=…, deadline_s=policy.llm_step_timeout_s, max_tokens=context_config.output_reserve)`
      （D3；工具顺序= registry 保序，回放确定性一环 tools.py:170–171）；
   8. `try: turn = await self._llm_step(messages, iteration)`——异常按 §4.4 矩阵处置
      （终止型先 `append(LLM_RESULT, {"iteration":…, "status":"failed", "cause":…})` 配对，
      再 `_terminate`；interrupted 型 append 配对后 `continue`——D10）；
   9. `append(LLM_RESULT, {…§4.6 键集, "status": "ok"})`；`tokens_used += input_est + output_est`；
   10. 分支（`_classify`，D7/D18）：
       - **violation**：`violations += 1`；`violations > policy.protocol_retry_limit` →
         `_terminate(PROTOCOL_VIOLATION, fallback=FALLBACK_PROTOCOL)`，return；否则
         `turns.append(Message(role="user", content=PROMPT_PROTOCOL_RETRY))`，continue；
       - **text**：`violations = 0`；`await self._finish_text(turn)`（挂点③：append
         ASSISTANT_MESSAGE `{"content": turn.text, "token_usage": turn.usage_completion}`）→
         `_terminate(COMPLETED, fallback=None)`，return；
       - **tools**：`violations = 0`（合法输出清零；D6 幻觉名在 `_run_tools` 内再计）；
         `turns.append(Message(role="assistant", content=turn.text, tool_calls=list(turn.tool_calls)))`；
         `reason = await self._run_tools(turn)`；reason 非 None → 已终止，return；否则 continue。
5. `_run_tools`（每个 call 顺序处理，D20）：
   1. 取消检查（同 4.1）；
   2. **重复检测（闸门 #4，D5）**：`key = (call.name, canonical_json(call.arguments_json))`；
      与 repeat_key 相同则 streak+1 否则重置 1；`streak > policy.repeat_call_limit` →
      `_terminate(REPEATED_CALLS, fallback=FALLBACK_REPEATED)` 返回 reason；
      `streak == policy.repeat_call_limit` → **不执行**，`_feed_tool_message(call, PROMPT_REPEAT_BREAK)`，
      处理下一个 call；
   3. **幻觉计数（D6）**：`registry.get(call.name) is None` → `violations += 1`（超限判定留到
      下一轮 violation 分支？否——立即判：`violations > protocol_retry_limit` → 终止
      PROTOCOL_VIOLATION）；
   4. `outcome = await executor.execute(call.name, call.arguments_json)`（写超时 30s、write-ahead、
      五结局全在 executor 内；基础设施异常 `EventStoreUnavailable`/`EventWriteFenced` **不接**，
      裸穿出 run——见 §4.4 末行）；
   5. 五结局 → 循环行为映射表：

      | OutcomeKind | 循环行为 | 依据 |
      |---|---|---|
      | OK | `_feed_tool_message(call, outcome.content)`（结果入上下文）→ 下一轮 | 03 §2 骨架 |
      | ERROR | 同上（错误文本回填，"它通常能自我修正"） | executor.py:28；03 §4 末行 |
      | RESULT_UNKNOWN | 同上（content 已含 X1 禁重试话术+引导查询确认，loop 不加工不终止） | executor.py:186–197 |
      | NEEDS_APPROVAL | **占位（K3）**：同上回填继续；单点分支注释 `# M2.9: 替换为挂起路径` | §3 K3 |
      | DISABLED | 同上（改道提示回填） | executor.py:123–128 |

   6. 每个 call 处理完 drain→yield（executor 的 tool_call/tool_result/tool_error 事件由 _Tap 捕获外流）。
6. `_terminate(reason, *, iteration, detail, fallback)`：fallback 非 None 时先
   `append(ASSISTANT_MESSAGE, {"content": fallback})`；再
   `append(LOOP_TERMINATED, {"reason": reason.value, "iteration": iteration, "detail": detail})`
   （cause 键可选，见 §4.6）；drain→yield。**COMPLETED 与 CANCELLED 与 GATEWAY_REJECTED 的
   fallback=None**（正常完成的 assistant_message 在 `_finish_text` 已发；取消无需话术；C6 禁话术）。

`_llm_step` 聚合（唯一允许的伪代码块之一，≤15 行）：

```python
async def _llm_step(self, ...) -> _LLMTurn:
    parts, calls, usage, stop = [], [], None, None
    stream = self._gateway.complete(req)      # def：调用即得 AsyncGenerator，不 await
    async with aclosing(stream):              # 提前退出时 GeneratorExit 传入生成器
        async for chunk in stream:
            if isinstance(chunk, TextDelta): parts.append(chunk.text)
            elif isinstance(chunk, ToolCallChunk): calls.append(chunk.tool_call)
            elif isinstance(chunk, UsageChunk): usage = chunk
            elif isinstance(chunk, StopChunk): stop = chunk
    if stop is None:   # 契约上不可能（终止哨兵见证）；防御性按违规形状返回
        return _LLMTurn(text="", tool_calls=(), stop_reason="end_turn", ...)
    return _LLMTurn("".join(parts), tuple(calls), stop.reason,
                    usage.model if usage else "", ..., cached=bool(usage and usage.cached))
```

`_make_summarizer`（伪代码块之二，D15，与常量 `_SUMMARIZE_PROMPT` 一起落 **runtime.py**
模块级私有——随其唯一调用方 `AgentRuntime.run`，两处调用见 §4.0/§4.2 步骤 6（tool_digest 道）
与步骤 7（summary 道））：

```python
def _make_summarizer(view: GatewayLike, tenant_id: str, session_id: str | None):
    async def summarize(text: str) -> str:
        req = LLMRequest(tier="fast", tenant_id=tenant_id, session_id=session_id,
                         messages=[Message(role="user", content=f"{_SUMMARIZE_PROMPT}\n\n{text}")])
        parts: list[str] = []
        async with aclosing(view.complete(req)) as stream:
            async for chunk in stream:
                if isinstance(chunk, TextDelta): parts.append(chunk.text)
        return "".join(parts)     # 失败不兜底：executor / builder 各自的 C34 fail-open 路径消化（D15）
    return summarize
```

## §7 陷阱与常见错误（症状 → 原因 → 正解）

1. **`await self._gateway.complete(req)` 报 "object AsyncGenerator can't be used in await"** →
   `GatewayLike.complete` 是 def，调用即返回 async 生成器（runtime.py:25–27）→
   `stream = gateway.complete(req)` 后 `async for` 消费；替身/测试假件同理用
   `async def complete(...)` + yield 实现（结构等价，router.py:190 同款）。
2. **写完 run() 调用处拿到协程不迭代、或函数体没有 yield 导致语义突变** →
   async 生成器规则：接线时删掉 runtime.py:44–45 的 `raise NotImplementedError` 与哨兵
   `yield` 两行后，函数体必须有真实 `yield`（委托循环：`async for ev in loop.run(...): yield ev`）；
   忘记 yield 会把 run 变成普通协程，`test_real_gateway_structurally_satisfies_protocol` 之外
   mypy 先红。
3. **`ProjectionError: assistant_message 事件 payload 缺少投影必需字段 'content'`，整个 append 回滚** →
   投影 payload 契约机器强制（store.py:276–284）→ 严格按 §4.6 表写键；user/assistant 必有
   `content`，闭合类必有 `tool_call_id`。
4. **给 LLM 步包 `asyncio.timeout(90)`** → C1 禁令（人肉算术会与 L1 三段超时打架，且挂起形态
   已由首块 25s/空闲 30s 守护）→ 闸门 #2 的实现**只是** `deadline_s=policy.llm_step_timeout_s`；
   00 §2.2 写的 `LLMRequest.deadline` 是简写，**字段真名 `deadline_s`**（schema.py:60）。
5. **凭记忆把异常写成 `GatewayTimeout`/`GatewayUnavailable` 等不存在的名字** → errors.py 只有
   §4.4 的六类（+不出网关的 ProviderError 家族）→ 引用前 Read errors.py；`except GatewayError`
   一把抓也是错——六类处置各不相同，且会误吞 ProviderError 泄漏这类 bug 信号。
