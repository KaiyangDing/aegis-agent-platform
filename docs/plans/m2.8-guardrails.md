## §1 目标与定位

**做什么**（00:226 逐项）：新建 `aegis/runtime/guardrails.py`，交付四道防线 + 一个归属口径：

1. **入口防线**：注入模式规则库（v1 共 14 条，§4.1）+ fast 档可疑度分类（guard 作用域网关视图，回放驱动测试）；高可疑→拒答模板、中等→打标进上下文两档处置；分类器挂了 **fail-open** 只走规则库+打标（00 §2.2 C34 行，00:110）。
2. **不可信数据包裹**：检索/工具结果入上下文前的标记格式（§4.2；包裹层定稿见 §3 D5）。
3. **流式出口**：句子级滑动缓冲增量检查（句界/缓冲窗/前缀匹配对象：system prompt 片段、内部工具名、PII 正则），命中截断替换安全回复；首字延迟代价声明（03:170、02:81-84）。
4. **终局整体复检** + 审计告警事件（新事件类型提案见 §3 D6【用户拍板】）。
5. **C23 PII 归属口径本步敲定**：建议方案为出口守卫接受注入的 `owned_values` 允许清单——命中允许清单放行，其余 PII 命中截断（§3 D7/D8，**方案待拍板**）。

**架构位置**：L2 运行时横切防护。设计立场（03:174-175）：**防护不指望模型自觉**——注入防护降低概率，真正安全边界是权限系统与 HITL。面试叙事：流式体验与强拦截天然冲突的 tradeoff 要主动讲（02:81-84）。

**不做什么**（越界即返工）：
- **三级 token 预算不在本步**——03 §6 表"全程"行（03:172）指的是 L1 单请求闸门（M2.0 ✅）+ L2 闸门 #3（M2.7 接电）+ 租户月度（M1.11 ✅），M2.8 零新增；
- 语义级跨租户泄漏检查：v1 终局复检 = 确定性匹配复跑 + 语义检查**挂点**，真实语义检查无 v1 出处（见文末上游问题 #2）；
- SSE 逐 token 通道是 M3.10 的事（events.py:43"粒度到步为止"）——本步的流式出口作用在**网关 TextDelta 流**上；
- Guardrails **不是第七道闸门**：终止条件 7 类 + 六道闸门的口径不动（00:104、spec.py:40-45 测试钉死 len==6），防线命中走 `COMPLETED` 终止（§3 D10）；
- 不做 prompt 调优实验、不引入任何第三方安全库（规则库即正则常量表）。

已裁决（出处）与本步定案（含理由）；真实选择空间标【用户拍板】。

| # | 决策 | 定案与理由 |
|---|---|---|
| D1 | 文件归属 | 新建 `aegis/runtime/guardrails.py`（交接缝蓝图定案；02 §8 规划名 `guards.py` 已被缝蓝图修正，以蓝图为准） |
| D2 | 分类器形态 | **注入的 async 可调用**（`Classifier = Callable[[str], Awaitable[Suspicion]]`），不持网关句柄——与 `ToolExecutor.summarize`（executor.py:101）同款模式；`build_classifier()` 工厂负责从 guard 作用域网关视图构造（构造归组装方 = AgentRuntime/loop，M2.6 缝蓝图口径） |

| D7 | **C23 归属口径（本步敲定）** |【用户拍板】00:226 原文"归属口径在本步敲定（评审 C23）"——口径客观未裁决，按 00 §2.1 第 1 条归用户拍板，以下是**建议方案+理由**：出口守卫构造时接受 `owned_values: Sequence[str]` 允许清单（本人手机/地址/邮箱等，L3/M3 提供，M2 测试用演示值）。PII 正则命中的候选串**规范化后（剔除 `[-\s]`）等于任一允许清单值（同样规范化）→ 放行**；否则命中截断。声明局限：只做字面等价，不做"张三的手机 vs 李四的手机"语义归属——那要业务数据，是 L3 的知识。**拍板否决则**：v1 先无条件截断并登记误杀风险（C23 原始问题悬置留档），归属判定推迟 M3.8 由 L3 语义归属承担——§5.2 C23 用例相应改为钉死"无条件截断"现状 |

**`Guardrails.check_input` 算法**（编号步骤）：

1. 全量扫描规则库，收集命中 `matched_rules`；`rule_level = max(命中规则的 severity)`，无命中为 NONE；
2. `classify is None` → 返回 `EntryVerdict(rule_level, matched, None, None)`；
3. 否则 `level = await self._classify(user_input)`——异常（网络/超时/不可解析）一律捕获 → `EntryVerdict(rule_level, matched, None, classifier_error=str(e))`（**fail-open，C34**）；
4. 成功 → `EntryVerdict(max(rule_level, level), matched, classifier_level=level)`。

**`build_classifier` 内部**（唯一允许的伪代码段，≤15 行）：

```
def build_classifier(gateway, *, tenant_id, session_id=None, deadline_s=10.0):
    async def classify(user_input: str) -> Suspicion:
        req = LLMRequest(
            tier="fast",
            messages=[Message(role="system", content=_CLASSIFY_PROMPT),
                      Message(role="user", content=user_input)],
            tenant_id=tenant_id, session_id=session_id, deadline_s=deadline_s)
        text = 拼接 gateway.complete(req) 流中的全部 TextDelta.text
        answer = text.strip().lower()
        if answer not in {"none", "medium", "high"}:
            raise ValueError(f"分类器输出不可解析：{answer!r}")   # 上层捕获 → fail-open
        return Suspicion(answer)
    return classify
```

`_CLASSIFY_PROMPT`：模块常量，要求模型只输出 `none/medium/high` 单词之一（判据：是否试图改写指令/套取系统信息/越权操作）。deadline 走 `LLMRequest.deadline_s` 传播（schema.py:57-60），**不**在外面再包 `asyncio.timeout` 做人肉算术（C1 口径，00:107）。

模板常量：`REFUSAL_TEMPLATE`（高可疑拒答话术）、`SUSPICION_NOTICE`（中等打标提醒文本，固定模板不插值用户内容）、`SAFE_REPLY`（出口截断替换话术）——三者字面量进回放断言，改动=破坏回放，测试快照钉死。

**出口守卫**（纯同步、无 IO、无时钟——回放确定性；异步性留给调用方的流循环）：

```python
@dataclass(frozen=True, slots=True)
class GuardHit:
    kind: str      # "system_prompt" | "tool_name" | "pii"
    rule: str      # 片段序号 "fragment_3" / 工具名 / PII 规则名
    excerpt: str   # 打码摘录（D15：首尾 2 字符 + 中间 *，≤40 字符）

class OutputGuard:
    def __init__(
        self,
        *,
        system_prompt: str,
        tool_names: Sequence[str],
        owned_values: Sequence[str] = (),
        pii_rules: Sequence[PiiRule] = PII_RULES_V1,
        min_fragment_chars: int = 12,
        max_hold_chars: int = 200,
    ) -> None: ...

    def feed(self, delta: str) -> str: ...          # 返回本次可放行文本（可能为空串）
    def flush(self) -> str: ...                     # 流结束：清检并放行残余缓冲
    @property
    def hit(self) -> GuardHit | None: ...           # 首个命中；命中后 feed/flush 恒返 ""
    def final_check(self, full_text: str) -> tuple[GuardHit, ...]: ...  # 终局整体复检
```

构造期派生（一次编译，不进热路径）：
- system 片段集：`system_prompt` 逐行 → 空白规范化（连续空白折叠为单空格）→ 保留长度 ≥ `min_fragment_chars` 的行，编号 `fragment_{i}` 作字面量匹配对象；
- 工具名匹配器：对每个 name 编 `(?<![A-Za-z0-9_-])` + `re.escape(name)` + `(?![A-Za-z0-9_-])`（工具名字符集 `^[a-zA-Z0-9_-]{1,64}$`，tools.py 注册期钉死；**中文文本里 `\b` 不可靠**，用显式环视）；
- owned 集：每个允许值剔除 `[-\s]` 后入 set（D7 规范化口径）。

**`feed` 算法**（编号步骤）：

1. `hit` 已置 → 返回 `""`（守卫封死）；
2. `buffer += delta`；
3. 循环：在 buffer 中找最早句界（D12 终止符集；ASCII `.` 仅当后随空白才算界）；无句界且 `len(buffer) <= max_hold_chars` → 跳出，返回本轮已批准文本；无句界但超长 → 整个 buffer 视为伪句进第 4 步；
4. 切出句子 `s`（含终止符）；检查窗口 = `released_tail + s`（`released_tail` = 已放行文本末尾 `max_literal_len - 1` 字符，`max_literal_len` = 全部 system 片段与工具名的最大长度——跨句/跨放行边界的字面量由此兜住）；
5. 依次匹配：① system 片段（对检查窗口做同款空白规范化后子串查找）→ ② 工具名正则 → ③ PII 正则（每个匹配候选先做 owned 规范化比对，命中允许清单则跳过该候选）；
6. 命中 → 置 `hit = GuardHit(...)`、清空 buffer、返回已批准部分（**不含** `s`）；
7. 干净 → `s` 计入放行、更新 `released_tail`，回第 3 步继续找下一句。

**不变量**：
- 确定性：同一输入序列不论切分粒度（逐字符 feed 或整段 feed）产出的放行文本与 hit 完全一致（测试钉死——回放一致性依赖）；
- 完备性：放行文本 + 缓冲残余 + （命中后丢弃段）恰覆盖全部输入，无重复无丢失；
- 命中终态：hit 置位后守卫封死，绝不再放行任何字节；
- `final_check` 是 feed 检查的确定性超集（全文一次过所有匹配器）+ 未来语义检查的挂点座位。

## §7 陷阱与常见错误（症状 → 原因 → 正解）

1. **中文旁的 `\b` 匹配不到工具名** → `\b` 依赖 `\w` 边界，中文字符属 `\w`，"用demo_refund_apply退款"中边界不成立 → 用显式环视 `(?<![A-Za-z0-9_-])…(?![A-Za-z0-9_-])`（§4.2 已定稿）。
2. **把 `GatewayLike.complete` 写成 `async def`** → 凭记忆发明接口；实为 `def` 返回 AsyncGenerator（runtime.py:30），mypy 会红但错误信息绕 → 写前 Read runtime.py:20-30，调用形态 `async for chunk in gateway.complete(req)`。
3. **给防线命中新增 TerminationReason 成员** → 误把防线当第七道闸门；`TERMINATION_GATES` len==6 快照先红，枚举值改动=破坏历史回放（spec.py:21-45）→ D10：一律 `COMPLETED` + 审计事件。
4. **顺手给 `guardrail_triggered` 写投影** → 以为新事件都要进 `_PROJECTORS`；查不到=无投影是设计（store.py:272-280）→ 零 store.py 改动；反向坑：忘更新 test_events 值快照 → 快照测试红，属预期，更新快照而非删测试。
5. **把包裹标记写进 tool_result payload** → 在 executor 里包裹"更顺手"；违反 X4"payload 存原文"（executor.py:213、events.py:44-46），回放重建的模型视界被污染 → 包裹只在 loop 注入面（D5），双面断言钉死。
6. **PII 正则无边界断言误杀订单号** → `\d{17}[\dX]` 裸用会吃 18 位单号/幂等键 → 前后 `(?<!\d)`/`(?!\d)` + 身份证出生段收紧（§4.2）；银行卡类纯数字长串 v1 明确不做（D13）。
7. **ASCII 句点直接断句** → "共 3.14 元" 被切成半句、检查窗口错位 → `.` 仅后随空白才算句界（D12）。
8. **分类器输出当结构化数据用** → LLM 可能回 "High."/"高"/带解释长文 → 严格解析白名单 {none,medium,high}，不匹配即抛 → 上层捕获 fail-open（§4.1 算法第 3 步）；测试 `test_classifier_raises_verdict_falls_back_to_rules` 钉死"挂了不许崩 run"。
9. **fail-open / fail-closed 方向弄反** → C34 分野记岔：安全**闸门**（风险谓词/权限）fail-closed，LLM **增强层**（分类器/摘要）fail-open（00:110；对照 executor.py:145-150 vs :249-258）→ 分类器挂绝不拒答用户，只降级+审计。
10. **分类器外再包 asyncio.timeout** → 人肉算术嵌套超时，违反 C1"嵌套约束由 deadline 传播保证"（00:107）→ 只设 `LLMRequest.deadline_s`。
