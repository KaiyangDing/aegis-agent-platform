## §1 目标与定位

**做什么**：新建 `aegis/runtime/replay.py`（进产品包——M4.3 CI 回归与 M2.11 录制脚本都要消费它，缝蓝图定案），一次交齐五件：

### 3.2 本步定案（蓝图未覆盖处；有唯一合理答案的直接定，附理由）

- **D1 cassette 顶层结构**：`{"format_version": 1, "session_id": str, "scopes": {道名: [entry, ...]}}`；entry = `{"request_digest": {...}(可省略，默认 {}), "chunks": [chunk, ...]}`。理由：顶层三键是任务定死的最小集；entry 只有两键——录制侧诊断域 + 回放本体，再多是注水。**手写资产的 `request_digest` 允许任意键子集或空对象**（load 不校验其形状，digest 仅供诊断不参与匹配）；"恰四键"的保证只属于 Recorder 产物（D2）——§4.1 手写样例只给两键即此口径。
- **D2 request 侧只记摘要域，不记 messages 原文**【用户拍板】：录 `{"tier", "message_count", "tool_names", "prompt_sha256"}` 四键（prompt_sha256 复用 cache.py:39 的语义本体口径：`model_dump(exclude={"request_id","session_id","tenant_id","deadline_s"})` → canonical JSON → sha256）。**建议采纳"只记摘要"**：① 敏感字段红线的机械保证——prompt 里的用户对话（潜在 PII）根本不落盘，比"录了再打码"可靠；② digest 仅供失配诊断与重录 diff 定位，**绝不参与匹配**（参与就变回 prompt 哈希）。替代方案（记全量 messages 便于重录 diff 逐句对照）的代价是每个 cassette 都成 PII 载体、`.gitignore` 与审查负担翻倍。若用户选全量，须同步加落盘前扫描与 README 审查项，**并同步改写按"只记摘要"落笔的下游条目**：§4.1 `request_digest` 签名注释、§4.3 README 骨架第 2 条、§5 `test_recorded_digest_is_summary_only`、§6"录 digest 不录 prompt 原文"验收项——不得静默保留摘要口径。
- **D3 chunk 原样全量录制**：响应 chunk 是回放本体，逐字段无损往返（chunk_list_adapter，schema.py:95）。PII 纪律由录制侧承担：M2.11 录制脚本只用虚构演示数据（云杉电商假租户）；README 重录流程含落盘后 `sk-` 扫描（网关侧 sanitize_error_text 已在源头打码 API key，base.py:52-62，且 LLMRequest/LLMChunk 字段中本就无 key——§0#5 已核）。
- **D4 v1 不支持异常/中断回放**：cassette 条目只有正常完整流。M2.12 的中断注入用测试侧包装器（包住 FakeGateway、在第 N chunk 后抛 `GatewayStreamInterrupted`）实现——那是消费方的测试道具，不是格式的一部分。理由：00:224 范围不含异常录制；格式一旦承载异常语义，format_version 升级成本立刻翻倍。
- **D5 Recorder 完整性守卫**：只有**自然走完**的流才入带（与 ExactCache 入库守卫同哲学，cache.py:55-60）；半截流（异常/消费方提前挂断）绝不入带，异常原样上抛。理由：半截流入带=把事故录成基线。
- **D6 游标推进时机**：FakeGateway 在 yield 首块**之前**推进道内游标——消费方即使首块前挂断也算一次调用，与真实调用语义一致；否则半途 break 会导致下次重复回放同一条目（静默错配，C10 病灶）。
- **D7 载入校验强度**：`Cassette.load` 构造期防呆抛 `ValueError`（与仓库惯例一致：构造期防呆用 ValueError，spec/tools/events 同款）：format_version ≠ 1、session_id 空、scopes 出现四道之外的键（拼错道名载入期就炸）、entry.chunks 为空或**不以 StopChunk 收尾**。chunk 字段坏（如 type 拼错）由 pydantic `ValidationError` 裸抛——bug 信号不包装。不强制含 UsageChunk（会话预算走 C25 估算不靠 usage，spec.py:56-58）。
- **D8 重录流程文档落点 = `tests/cassettes/README.md`**：与资产同目录同仓库、M4.3 的 PR 审查可直接链接；docs/ 目录 M4.7 才迁入仓库，放那里 CI 引用不到。
- **D9 四道道名与调用源映射（钉死，防 summary/tool_digest 张冠李戴）**：

  | scope 字面量 | 调用源（00:224 原文） | 接线方 |
  |---|---|---|
  | `"main"` | 主循环 | M2.7 AgentLoop 调网关 |
  | `"summary"` | 滚动摘要 | M2.5 ContextBuilder 的摘要钩子（M2.7 组装时从 scoped 视图构造） |
  | `"guard"` | 守卫分类 | M2.8 入口 fast 档可疑度分类 |
  | `"tool_digest"` | 结果摘要 | ToolExecutor 的 `summarize` 钩子（executor.py:101） |

- **D10 统一取视图入口**：模块级 `scoped_view(gateway, scope)` + `@runtime_checkable` 协议 `SupportsScoped`——有 `scoped` 方法（FakeGateway/Recorder）→ 返回对应道视图；没有（真实 LLMGateway）→ **直通返回自身**。理由：组装方（M2.7）拿到的是 GatewayLike，不该 if/else 判类型；直通语义由单点函数兑现。`FakeGateway.complete` ≡ `scoped("main").complete`（FakeGateway 自身满足 GatewayLike，`AgentRuntime(fake)` 直接可用）。
- **D11 原子落盘**：同目录临时文件 + `os.replace`（Windows 上 `os.rename` 目标存在时抛 FileExistsError，`os.replace` 才覆盖；tmp 必须与目标同目录——跨卷 replace 非原子）。编码 UTF-8、`ensure_ascii=False`、`indent=2`、`newline="\n"`（`.gitattributes` eol=lf，06 §4）。不做目录 fsync（测试资产非事务数据，显式取舍）。
- **D12 C31 归一化规范**：见 3.3 字段表。豁免键只在 **payload 顶层**滴除（递归滴除是过度工程且会误伤 result 原文里的同名业务字段）；配套对齐要求见 §2.2。
- **D13 Scope 类型用 `Literal`**：`Scope = Literal["main", "summary", "guard", "tool_digest"]` + 常量 `SCOPES` 元组。不用 StrEnum：道名进 JSON 文件与函数参数，Literal 让 mypy 在调用点拦拼写错误，且无枚举序列化噪音。
- **D14 `assert_exhausted()` 提供但不强制**：M2.12 强断言场景（行为轨迹变短也是漂移）必须调用；普通单测可选。不做成 pytest 自动 fixture——隐式断言会让局部性测试莫名其妙红。

| 事件在流中的相对序 | **参与**（列表顺序承载） | 行为轨迹的骨架 |

**load 算法**：
1. `json.loads(path.read_text(encoding="utf-8"))`；
2. `format_version != FORMAT_VERSION` → `ValueError`（报文件路径与两个版本号）；
3. `session_id` 缺失或空 → `ValueError`；
4. `scopes` 的键出现 `SCOPES` 之外的名字 → `ValueError`（点名坏键与合法四道——拼错道名在载入期爆炸，不留到回放期）；
5. 每条 entry：`chunks = tuple(chunk_list_adapter.validate_python(entry["chunks"]))`（pydantic 判别联合还原真类型，坏 chunk 由 ValidationError 裸抛）；chunks 为空或末元素非 `StopChunk` → `ValueError`（完整流口径，cache.py:56 同源）；`request_digest = entry.get("request_digest", {})`；
6. 构造 frozen `Cassette`（scopes 值全部 tuple——加载后只读）。

**save 算法**（Recorder 与手工资产共用）：
1. `payload = self.dump()`——chunks 经 `chunk_list_adapter.dump_python(list(entry.chunks), mode="json")` 导出；键序固定为 format_version → session_id → scopes；
2. `text = json.dumps(payload, ensure_ascii=False, indent=2) + "\n"`；
3. 同目录临时文件：`tmp = path.with_name(path.name + ".tmp")`；`tmp.write_text(text, encoding="utf-8", newline="\n")`；
4. `os.replace(tmp, path)`（原子覆盖，Windows/Linux 通用）。

## §7 陷阱与常见错误（症状 → 原因 → 正解）

1. **凭记忆把协议写成 `async def complete`** → 症状：mypy 报 FakeGateway 不满足 GatewayLike，或调用侧写 `await gw.complete(req)` 拿到协程不是流 → 原因：async 生成器方法的类型是"调用后返回 AsyncGenerator"，协议声明是 `def`（runtime.py:25-27）→ 正解：实现用 `async def complete(...) -> AsyncGenerator[LLMChunk]:` + yield（router.py:190 同款）；调用侧 `async for chunk in gw.complete(req):`，没有 await。
2. **自写 if/else 反序列化 chunk** → 症状：新增 chunk 字段时静默丢字段/类型错 → 原因：绕过判别联合适配器=第二事实源 → 正解：只用 `chunk_list_adapter.validate_python / dump_python(mode="json")`（schema.py:94-95）。
3. **匹配键混进 prompt 哈希** → 症状：改一个字的 system prompt 后全量 CassetteMismatch → 原因：违反 03:197 明文（prompt 微调不至于全量 miss）→ 正解：digest 只进诊断信息；`test_prompt_drift_does_not_miss` 反向钉死。
4. **四道装成一道全局计数** → 症状：加了滚动摘要后主循环回放错位、拿到摘要文本当回复 → 原因：C10 的病灶（00:224）→ 正解：`_cursors` 按道分账；交错调用测试钉死。
5. **游标在流耗尽后才推进** → 症状：消费方半途 break 后，下一次调用重复拿到同一条目（静默错配）→ 原因：推进时机放在 yield 循环之后，GeneratorExit 跳过它 → 正解：D6——取到条目立即推进，再开始 yield。
6. **Windows 原子写用 os.rename / tmp 放系统临时目录** → 症状：`FileExistsError`，或断电后半截文件 → 原因：Windows rename 不覆盖；跨卷 replace 非原子 → 正解：同目录 `.tmp` + `os.replace`（D11）。
7. **cassette 中文变 `\uXXXX` / CRLF 入库** → 症状：git diff 不可读、`.gitattributes` 告警 → 原因：json.dumps 默认 ensure_ascii=True；write_text 默认平台行尾 → 正解：`ensure_ascii=False` + `newline="\n"` + encoding="utf-8"；PowerShell 查看用编辑器或 `Get-Content -Encoding utf8`（06 §4 第 3 条管道乱码坑）。
8. **Recorder 忘关内层流** → 症状：M2.11 真实录制时连接泄漏/挂起（httpx 池耗尽抛 GatewayOverloadedError）→ 原因：外层生成器被 aclose 时内层 AsyncGenerator 没人关 → 正解：`finally: await stream.aclose()`（resilience.py:79-80 归还连接的同款纪律）。
9. **把半截流录进 cassette** → 症状：回放基线里躺着一条没有 StopChunk 的流，M2.7 循环解析卡死 → 原因：录制在 except/finally 里也 append → 正解：D5 完整性守卫（done 标志在 async for 自然结束后置位）+ load 的"以 stop 收尾"校验双保险。
10. **给 AgentEvent 虚构时间戳豁免** → 症状：normalize 规范里出现 "timestamp"/"created_at" 豁免项 → 原因：凭记忆以为事件有时间戳 → 正解：AgentEvent 无时间戳字段（events.py:6），墙钟在 DB 列（store.py），根本流不进 AgentEvent；豁免表以 §3.3 为准，一个不多一个不少。
11. **豁免键递归滴除** → 症状：工具 result 原文里业务字段 `usage` 被误删，等价断言假绿 → 原因：把顶层语义做成了深度遍历 → 正解：D12 只滴 payload 顶层；M2.7 按 §2.2 对齐要求把豁免字段放顶层。
12. **顺手扩权**：给 cassette 加异常回放/给 LLMRequest 加 scope 字段/顺手重构 executor 的 payload 键名 → 全部越界（§1 不做清单；缝蓝图明确不动 L1 schema）。发现"不改上游做不了"→ 停下报用户，不许自行改。
13. **收集数错报** → 症状：预告 +30 实收 +28，验收对账翻车 → 原因：合并断言/参数化后没重数 → 正解：交付前跑 `uv run pytest --collect-only -q tests/runtime` 用数字说话（M2.4 偏差登记在案，00 §6.3）。
14. **交付正文被工具调用吞掉** → 症状：只有 Write/Edit 调用，四件套讲解没进回复正文 → 正解：讲解与指令块必须在助手回复正文里，文件只装代码与测试（00 §2.1 交付四件套）。
