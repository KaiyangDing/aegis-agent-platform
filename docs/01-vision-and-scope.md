# 01 · 愿景与范围

## 1. 背景

原型级的 Agent（一个 while 循环 + 几个工具 + 一段 prompt）与企业可用的 Agent 系统之间，
隔着七类工程问题：循环失控、工具不可信、上下文爆炸、上游故障、并发与成本、不可观测、不安全。
本项目的目的就是把这七类问题**逐一做成可演示、可量化、可深挖的工程实现**。

## 2. 为什么不是"直接调大模型"

| 维度 | 裸调 LLM | Aegis 平台层 |
|---|---|---|
| 数据 | 只知道训练数据 | 多租户 RAG，租户间行级隔离 |
| 行动 | 只能生成文本 | 工具调用；高危操作过 HITL 闸门 |
| 状态 | 无状态 | 会话管理、上下文分层编译与滚动摘要（跨会话长期记忆列 v2，接口已预留——00 §10.1 #20 拍板 2026-07-24）、事件流断点续跑 |
| 可靠性 | 上游故障直接砸给用户 | 重试 / 熔断 / 多供应商 fallback / 转人工兜底 |
| 成本 | 每请求全价大模型、无上限 | 档位路由、租户隔离缓存、三级 token 预算 |
| 安全 | 输入直通模型 | 注入防护、PII 脱敏、审计留痕 |
| 质量 | 改 prompt 凭感觉 | 评测集 + CI 回归，量化对比 |
| 排障 | 只有一个 500 | 全链路 trace，每步输入输出可查 |

一句话：**LLM 是 CPU，Aegis 是操作系统。**（完整论证：[ADR-001](adr/ADR-001-why-platform.md)）

## 3. 目标（按优先级）

1. **平台能力完整**：L1 网关、L2 运行时、L3 业务三层各自独立可测试，横切能力（可观测 / 安全 / 交付）贯穿三层；
2. **指标可量化**：成本下降比例、P99 延迟、评测通过率、熔断恢复时间——简历上的每个数字都有测量方法；
3. **面试可深挖**：每个关键决策有 ADR，每个模块有"为什么这么做、还考虑过什么、代价是什么"的完整答案；
4. **可演示**：15 分钟内能跑通的 demo 脚本——多租户隔离、流式回复、工具调用 + 人工确认、故障注入下的熔断与 fallback、断点续跑。

## 4. 非目标（刻意不做，防止范围蔓延）

| 不做 | 理由 |
|---|---|
| 微信 / 邮件 / 电话等多渠道接入 | 渠道适配是体力活，不体现核心能力；只做 Web + REST API |
| 精美前端 | 提供最小可用的聊天页（单文件、无构建链）；坐席审批为 API + curl 演示（审批页 stretch，见 04 裁剪表），重心在后端 |
| 模型训练 / 微调 | 平台工程项目，模型即服务 |
| K8s 生产级部署 | Docker Compose 起全栈 + 多副本演示水平扩展；K8s 清单只写文档不实操 |
| 通用 Agent 市场 / 低代码编排 | 那是产品化方向，会稀释平台层的深度 |
| 多区域 / 异地容灾 | 超出单人项目合理范围，面试被问到时能讲思路即可 |

另有一批**规划期即裁剪进 v2** 的项（语义缓存、A/B 灰度、坐席审批页、Ollama 本地档、
坐席实时接管等）——不是"不做"，是"设计已预留、排期上诚实"，完整清单见
[路线图·规划期裁剪表与 v2 展望](04-roadmap.md)。

## 5. 演示场景设定

虚构 SaaS 公司「云杉电商」的客服系统，预置两个租户：

- **租户 A（数码商城）**：知识库为产品手册 + 售后政策；工具为订单查询、物流查询、退款申请
  （退款 > 200 元需人工确认——200 元是**租户 A 的配置项**（`tenants.config.approval_threshold`），
  由工具的 risk_policy 读取，不是写死在代码里的常量）；
- **租户 B（生鲜超市）**：知识库为配送范围 + 会员规则；工具为订单查询、优惠券补发。

两个租户的数据必须互相不可见——这是多租户隔离的验收场景。

## 6. 成功标准

- [ ] Demo 脚本 15 分钟跑通全部亮点（含故障注入演示）；
- [ ] 评测集 ≥ 30 条用例（M3 种子 15–20 条，M4 扩充），双流水线：CI 回放回归（行为断言）+
      LLM-as-judge 离线质量评测，通过率有基线和趋势；
- [ ] 压测报告（两组口径分开）：模拟上游延迟下的多副本平台开销 P50/P99 + 小样本真实首 token 分布；
- [ ] 成本对照实验（两组分开、口径写死）：档位路由降本在全唯一问题集上实测；
      精确缓存降本在声明分布假设的模拟流量上实测——产出实测数字与口径说明，不预设目标值；
- [ ] 每篇 ADR 都能支撑 5 分钟以上的面试深挖对答。
